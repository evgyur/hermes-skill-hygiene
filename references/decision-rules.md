# Decision rules

A skill is useful when it supplies information or constraints the current task would otherwise lose. Assess value against the actual installed runtime and selected model, not a generic notion of intelligence.

## Keep

Keep owner/routing maps, exact APIs, managed runtime commands, approval gates, delivery/privacy limits, source provenance, known failure recovery and tested acceptance criteria. Keep rare workflows unless their owner explicitly retired them. Keep a disabled skill disabled; its visibility is not a cleanup decision.

## Consolidate

Consolidate duplicated doctrine only after mapping all unique obligations to a canonical owner. Preserve explicit aliases as thin routers, the full brief, output contract and effect boundary. Keep historical text outside normal execution paths when authorized; do not copy a source tree just to maintain an alias.

## Split

A root should expose triggers, hard constraints, common workflow, task routing and done criteria. Move complete specialist branches into references. Bind each original byte/range to exactly one retained target. Measure primary-load bytes separately from optional references and whole-prompt size. Never say a byte reduction is a latency benchmark.

## Repair

A malformed frontmatter field, broken alias or wrong relative path is a defect when the actual consumer fails. Human-readable names and source snapshots can be accepted by one runtime but not portable to another: test the consumer before renaming an identifier. Do not fix a template URL or an immutable historical reference as if it were an active dependency.

## Hold

Hold a source-owned change, unreadable document, native-manager guard failure, raw historical snapshot or protected effect with exact evidence. A reviewed exception needs an individual finding ID and a reason; it does not erase the finding or certify unread content. Re-review on source/stat change. Do not silently change permissions, weaken validators, retire features or migrate owners.
